# ⚙️ Pipelined RISC-V Processor (64-bit)

<div align="center">

**A 64-bit 5-stage pipelined RISC-V processor (RV64I) implemented in Verilog HDL, designed and verified using Xilinx Vivado.**

</div>

---

## 📖 Overview

This project implements a **64-bit pipelined RISC-V processor (RV64I subset)** using Verilog HDL.  
Compared to a 32-bit design, this processor supports wider datapaths, extended address space, and 64-bit arithmetic operations.

The architecture uses a **classic 5-stage pipeline**, with hazard management logic to ensure correct execution under data and control dependencies.

---

## 🧠 Pipeline Architecture

| Stage | Description |
|------|------------|
| IF   | Instruction Fetch from instruction memory |
| ID   | Instruction Decode + Register Read |
| EX   | ALU operations / branch evaluation |
| MEM  | Data memory access (load/store) |
| WB   | Write results back to register file |

### Pipeline Registers
- IF/ID  
- ID/EX  
- EX/MEM  
- MEM/WB  

These registers enable **parallel instruction execution** across stages.

---

## 🔁 Instruction Flow

At any given clock cycle:
- Up to **5 instructions** are active simultaneously
- Each instruction is processed in a different pipeline stage

---

## ✨ Features

- 64-bit **RV64I Instruction Set Support**
- **5-stage pipelined datapath**
- **64-bit ALU and datapath**
- **Hazard detection and resolution**
- **Forwarding (bypassing) unit**
- **Pipeline stalling (load-use hazard handling)**
- **Pipeline flushing for branch hazards**
- Modular and scalable Verilog design
- Verified using simulation in Vivado

- Multiplexers

### Control Components
- Main Control Unit
- ALU Control Unit
- Hazard Detection Unit
- Forwarding Unit

### Pipeline Registers
- IF/ID Register  
- ID/EX Register  
- EX/MEM Register  
- MEM/WB Register  

---

## ⚠️ Hazard Handling

### 1. Data Hazards
Handled using:
- **Forwarding Unit**
  - EX → EX forwarding  
  - MEM → EX forwarding  

- **Stalling**
  - Applied in load-use hazards

---

### 2. Control Hazards
Handled using:
- **Pipeline flushing**
- Branch resolution in EX stage

---

## ⚙️ 64-bit Specific Design Considerations

- **Address Alignment:**  
  - Memory accesses are **8-byte aligned**  
  - Address indexing uses `Address[63:3]`

- **Register Width:**  
  - All registers are **64-bit wide**

- **Instruction Compatibility:**  
  - Supports RV64I base instructions  
  - Proper sign-extension for 32-bit immediates

## 🚀 Getting Started

### Prerequisites
- Xilinx Vivado (2020.x or later)

---

### Installation & Setup

1.  **Clone the repository**
    ```bash
    git clone https://github.com/KrushnSurlakar/RISC-V-64-bit-Pipelined-Processor.git
    cd Pipelined-RISC-V-Processor
    ```

2.  **Open the project in Vivado**
    -   Launch Xilinx Vivado Design Suite.
    -   Select `Open Project` from the start page or `File > Project > Open`.
    -   Navigate to the cloned repository directory and select the `RISC_V_PROCESSOR.xpr` file.

3.  **Explore the design**
    -   Once the project is open, you can view the source files under `Design Sources` in the `Sources` window.
    -   Examine the block diagrams, RTL schematics, and individual Verilog modules.

## ⚙️ Usage & Development Workflow

Once the project is opened in Xilinx Vivado, you can perform the following key actions:

### Running Simulation

1.  In the `Flow Navigator` on the left, expand `Simulation`.
2.  Click on `Run Behavioral Simulation`. This will compile your Verilog source files and run the defined testbench.
3.  The `Waveform` window will appear, displaying the simulation results. You can add signals of interest to visualize their behavior over time.

### Synthesis & Implementation

If you wish to synthesize the design and potentially implement it on a target FPGA:

1.  **Synthesize Design**: In the `Flow Navigator`, click `Run Synthesis`. This step translates your Verilog code into a gate-level netlist.
2.  **Implement Design**: After successful synthesis, click `Run Implementation`. This includes placement and routing for a specified target device.
3.  **Generate Bitstream**: If a target FPGA is set up (via `.xdc` constraint files in `RISC_V_PROCESSOR.srcs/constrs_1`), you can generate a bitstream file (`.bit`) that can be loaded onto an FPGA.
